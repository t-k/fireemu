Local emulator for Firebase

Test Firebase apps locally,
closer to production.

Fireemu runs Firestore, Authentication, Storage, Functions, Pub/Sub and Eventarc on your machine and in CI. It catches what the official emulator misses, supports features it lacks, and lets you control time.

Features

Passing tests against the official emulator does not always mean production will behave the same way. Fireemu is built to close those gaps.

Production-level validation

Detects configuration problems that only surface in production, such as missing Firestore composite index definitions.

Features the official emulator lacks

TOTP multi-factor authentication, password policies, tenants, quota simulation, App Check debug tokens and more.

Control over time

Pin a virtual clock, advance it, and run scheduled functions immediately — no waiting for the real schedule.

Two compatibility profiles

strict follows production Firebase; emulator follows the pinned official emulator. Test against either or both.

Parallel test worlds

fireemu/testing creates isolated, resettable worlds — each with its own daemon, ports, clock, Rules and state.

Fast and light

A native binary that starts in ~140 ms and idles at ~11 MiB, with a built-in UI for data, functions and logs.

Installation

Fireemu ships through npm with a prebuilt binary for each platform. Node.js 20 or newer is required.

1. Install

npm install --save-dev fireemu

2. Initialize

npx fireemu init        # interactive
npx fireemu init --yes  # CI / scripted

Creates fireemu.json. You can choose a compatibility profile and reuse an existing firebase.json — rules, indexes, Functions codebases and ports are read from it at every start.

3. Check the environment

npx fireemu doctor

Usage

Start the emulator

npx fireemu up
npx fireemu up --only auth,firestore,storage
npx fireemu up --only functions:<codebase>

Run a command against it

npx fireemu exec -- npm test
npx fireemu exec --only auth,firestore -- npm test
npx fireemu exec --ui -- npm test

exec sets the Firebase SDK emulator host variables for the child, forwards SIGINT/SIGTERM and returns its exit status.

Official CLI aliases

npx fireemu emulators:start
npx fireemu emulators:exec -- npm test
npx fireemu emulators:export ./emulator-data

Web UI

Browse and edit data, inspect registered functions, invocations and logs, run scheduled functions now, or advance the virtual clock. Default address http://127.0.0.1:4000; change it with --ui-port, disable with --ui-port 0.

Parallel test worlds

import { withTestWorld } from 'fireemu/testing';

await withTestWorld({
  projectId: 'demo-test',
  clockStart: '2026-01-31T23:59:00Z',
  services: ['auth', 'firestore'],
}, async world => {
  await world.clock.advance(59999);
  await world.run(process.execPath, ['./test.mjs']);
});

Configuration

{
  "$schema": "https://fireemu.dev/spec/config/fireemu.schema.json",
  "schemaVersion": 1,
  "profile": "strict",
  "firestore": {
    "edition": "standard",
    "apiMode": "native"
  },
  "daemon": { "clockStart": "2026-01-31T23:59:00Z" }
}

Use --config ./fireemu.json to choose a file. See the configuration schema for every setting.

Compatibility profiles

ProfileBehavior
strictMatches production Firebase behavior and constraints as closely as possible. Default.
emulatorTargets a pinned version of the official emulator.

Notable settings

  • auth.signIn, auth.passwordPolicy — sign-in methods and password rules
  • auth.mfa, auth.totp — TOTP multi-factor authentication
  • auth.tenants, auth.multiTenant — tenants at start
  • auth.quotaSimulation — sign-up quota exceeded
  • scheduler.* — catch-up, overlap and time zone
  • firestore.history, storage.maxStoredBytes — memory limits
