# Pub/Sub authentication on the local endpoint

This contract is defined before implementing authentication admission. It applies to the loopback Pub/Sub endpoint in the strict profile, including REST, native gRPC and opening StreamingPull.

Requests without Authorization, X-Goog-Api-Key, access_token or key query parameters are accepted. This is an explicit production divergence for credential-free clients using `PUBSUB_EMULATOR_HOST`, rather than a claim that production permits anonymous requests. The Node Pub/Sub SDK selects insecure channel credentials for an emulator endpoint in [`determineBaseUrl_`](https://github.com/googleapis/google-cloud-node/blob/pubsub-v5.3.1/handwritten/pubsub/src/pubsub.ts). In the published `@google-cloud/pubsub` 5.3.1 source this is `build/src/pubsub.js:366–372`. The published `google-gax` 5.0.8 source, `build/src/grpc.js:184–186`, returns those explicit credentials before attaching the Google credential metadata generator at lines 192–202. Consequently this gRPC SDK path does not add an Authorization header. These versioned package sources can be read without loading client credentials.

Credential presence is the exact boundary: Authorization and X-Goog-Api-Key headers, and case-sensitive access_token and key query names, count even with empty values or duplicates. Percent-encoded query names are decoded; credential values are never decoded or inspected. Empty values, whitespace, unsupported schemes, `Bearer owner`, opaque values, unsigned JWTs and altered JWTs are present credentials, never anonymous requests. No trimming, token parsing failure or duplicate selection widens the credential-free exception. Query names such as Access_token, access-token, key_suffix and api_key are different names. A malformed unrelated parameter cannot hide a recognized credential in another pair. The emulator profile retains its existing credential-independent behavior.

The alternate query and API-key inputs were not recorded against production. Their local refusal deliberately uses the assigned 401 contract; this is not an observation that production gives the same status or error details for those carriers. The existing recorded envelopes remain the evidence for the error's semantic shape.

## REST fallback in the pinned Node SDK

`PUBSUB_EMULATOR_HOST` does not make the default REST fallback credential-free. In google-gax 5.0.8, `build/src/fallback.js:266–268` calls `auth.getClient()` even when emulator gRPC credentials were supplied; the REST protocol defaults to HTTPS at line 289. Its nested google-auth-library 10.5.0 proceeds to ADC discovery unless authentication was explicitly configured. A supplied projectId prevents the separate project-discovery call but does not remove this REST credential-acquisition path.

For an explicitly anonymous local REST client, supply `fallback: 'rest'`, `protocol: 'http'`, a dummy projectId and `auth: new PassThroughClient()` resolved from the SDK's google-auth-library dependency. PassThroughClient forwards requests without authentication. The actual SDK transport test observes no Authorization header with this configuration. Its default-fallback counterexample intercepts credential acquisition before ADC runs, and guards both the SDK's google-auth-library 10.9.1 and gax's nested 10.5.0 copy. These are unary REST transport checks; they do not establish StreamingPull support or production authentication.

Local verification currently has no configured Google OAuth issuer, trusted signing keys, token introspection service or accepted credential type. Its supported credential set is therefore empty. Every presented credential fails local verification as unsupported; no credential contents are decoded or treated as an identity. In particular, structurally plausible tokens and Firebase ID tokens do not prove Pub/Sub OAuth authentication. This limitation also rejects valid production OAuth credentials on the local endpoint. Such credentials must not be described as invalid in production, and their production behavior remains unobserved here. Supporting a nonempty credential set requires a separate explicit trust contract and cryptographic verification; it must never fall back to anonymous access.

A failed local verification produces HTTP 401 with `UNAUTHENTICATED` on REST, or native gRPC code 16 with the same recorded authentication message. The recorded REST GetTopic, CreateTopic and Publish envelopes include `google.rpc.ErrorInfo`, reason `CREDENTIALS_MISSING`, service `pubsub.googleapis.com` and their respective Publisher method. These shapes are grounded in the production authentication observations for those three operations. Other credential/method combinations are not claimed as production observations. Strict REST JSON uses two-space indentation, one final newline and protobuf field order; emulator REST retains its existing compact encoding. Map-key order and previously unobserved error-detail layouts retain deterministic local ordering without additional production claims.

Admission occurs before REST JSON parsing, gRPC message decoding or broker mutation. A rejected create or publish cannot change resources, advance message identities or publish an event. Tests cover both profiles, headerless requests, immediately adjacent present-header shapes, duplicate headers, the three recorded envelopes, native StreamingPull and a state reference model across accepted and rejected operations.

## Strict release note

A client supplying a valid Google OAuth token receives HTTP 401 from the strict local Pub/Sub endpoint because the local supported credential set is empty. Production can accept that credential. This affects, for example, a Java client configured without NoCredentialsProvider, and a default credential-bearing Node REST fallback client. Use an explicitly credential-free local client when exercising the declared anonymous development exception.
