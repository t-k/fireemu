# Shared production reservations

This internal one-host library extends the existing Gate file protocol with cross-campaign admission. It does not approve production permission, run a scheduler, acquire credentials, or execute a campaign. O7 must validate the owner envelope and exact manifest, then use one canonical shared directory for every worker. A separate directory per campaign would defeat shared admission and is not an allowed production configuration.

`Ledger.create(path)` initializes a new private directory once. `Ledger(path)` requires existing state and never creates a fallback. Tickets bind the canonical ledger path and identity, the campaign claim digest, and the envelope digest. A copied ledger at another path cannot consume the original ticket. State remains bounded to 10,000 reservations and 16 MiB; reaching either local bookkeeping limit refuses new admission.

## Admission and accounting

`reserve(envelope, claim, gate_plan, *, generation=None)` atomically checks the permission window, envelope scope, exact Gate plan, fresh nonce/Gate path, active lock conflicts, concurrency, and every budget dimension before persisting a reservation. Budget dimensions are integer upper bounds for requests, accounts, resources, and micro-USD. The full campaign allocation stays allocated permanently, including unused capacity. Release never refunds it. This conservative first version avoids treating a failed or ambiguous attempt as unused capacity; allocations are upper bounds, not measured cloud charges.

The existing campaign Gate remains responsible for per-attempt counting, deadlines, cost, ownership proofs and conditional cleanup. There is no second per-request accounting protocol. The shared ledger checks that the declared campaign allocation covers the Gate's observation/recovery/management request ceiling, cost ceiling, resource count, and duration. Owned Firestore document resources must be covered by a declared WRITE or EXCLUSIVE scope. O7 must separately bind account counts and every configuration/metadata dependency to the exact manifest; resource coverage alone does not establish those dependencies. A production Gate's permission digest must match the envelope permission digest. One permission digest cannot be reused with a different envelope.

Lock keys are project-qualified, segment-preserving paths, for example `project/fireemu-35fe6/firestore/(default)/documents/oracle/<nonce>/limits-02/*`. Only a terminal `/*` is accepted. Empty segments, dot segments, percent encodings and interior wildcards are rejected. Parent and child scopes overlap; siblings do not. Overlapping READ locks are compatible; any overlapping WRITE or EXCLUSIVE lock conflicts. Conflicts apply across envelopes, not only within one permission.

## Per-task budget

The owner's US$10 authorization is per production observation task, identified by the claim's `campaignId` (`FS-LIMIT-API-REQUEST-BYTES`, for example), and never cumulative across the program. Everything a task ever charges counts against that task's US$10: preparation, failed attempts, retries, re-checks after a fix and recovery. Independent tasks each have their own US$10. The program-wide total is reported by the operator's frame but is never a stop condition in this library.

`reservations.task_budget_check(ledger_state, campaign_id, new_cost_microusd, cap_microusd=10_000_000)` (defined in this module, so the Commit lane's unlinked archive closure stays a single file) sums the `costMicrousd` allocation of every reservation whose claim names the task, in every state (`held`, `closing`, `released`, `aborted-no-data`, `closed-after-escalation`, `closed-after-abandon`), adds the new claim and refuses when the sum exceeds the cap. Every state counts because the Ledger never refunds an allocation. `Ledger.reserve` calls it inside the ledger lock, after the per-envelope checks and before anything is persisted, so every O8 lane gets the rule without a lane change; the refusal is `task-budget-exceeded:<campaignId>` and leaves the state file unchanged. The existing per-envelope limits and concurrency are unchanged and still apply on top.

The task a claim names must be a catalogued production observation task: `CATALOGUED_CAMPAIGN_IDS` is the closed literal set of the stable campaign ids the lanes declare, without attempt or version suffixes (the write-txn stream lane's `-V2`..`-V9` records are re-checks of the one task `FS-WRITE-TXN-PRECEDENCE-01`). `reserve` refuses any other id as `uncatalogued campaign id: <id>` before touching the ledger, because a claim that named its nonce, a fixture label or a versioned id would earn itself a fresh US$10 per attempt. Rows already written are not re-validated against the set; a reservation is history once it exists. Adding a task means adding its id to the literal and to `test_every_lane_descriptor_campaign_id_is_catalogued`, which reads each lane's declared constant out of its source and checks it is listed.

Regression tests in `test_task_budget.py`: independent A at US$8 and B at US$8 are both admitted; A at US$8 followed by a retry of A at US$3 is refused; A at US$8 followed by a recovery-only claim of A at US$1 is admitted (9 <= 10); a task whose earlier row is still held counts exactly as a retired one; exactly the cap is admitted and one micro-USD over is refused.

## Lifetime and cleanup

A reservation remains held after its deadline or worker exit. Neither a PID sweep nor expiry releases ownership. `validate(ticket)` refuses new work after the deadline or while the reservation is closing/released. Real time is sampled inside the acquired ledger lock, so waiting for admission cannot preserve an expired time check. No plaintext credential is stored in this ledger.

`finish(ticket)` first changes the lease to closing, then releases the ledger lock before reading the registered Gate. Dispatch must check the lease before transport. This lock order prevents a Gate-to-ledger/ledger-to-Gate deadlock. Release requires the exact frozen Gate plan, no in-flight work, every job marked complete, all assigned resources confirmed absent, and counters within the original allocation. An incomplete Gate restores the held state for bounded recovery; interruption during finalization retains the closing state and requires explicit recovery. Successful finalization releases locks and concurrency only, retaining the claim, nonce, allocation, and final Gate digest.

The evidence contract admits any preflight stop point. The production preflight charges two credential slots and then makes four privileged metadata observations, `project`, `database`, `auth` and `key`, in that order, and an attempt can stop at any of them with no data request sent. A receipt is accepted when `managementUsed` is the two credential slots followed by a prefix of those four, and the receipt's `metadata` ids are that same prefix or one shorter: a slot is charged before its evidence is appended, so a stop at the baseline comparison leaves the two equal and a stop in the transport leaves `metadata` one shorter. Alongside that, the receipt must prove positively that nothing was dispatched: no collection, `productionExecuted` false, charged calls equal to the management slots used, no recovery, and every job with zero observations, no owned resources, no creation proofs and no absence claims.

`abort_no_data(ticket, record)` is a separate terminal transition for the reviewed Commit acquisition failure before any data dispatch. The record has the closed kind `shared-no-data-abort-v1` and binds the exact ticket, plan digest, pre-abort Gate digest, canonical persisted `receipt.json` path and digest, frozen collector source digest, source commit, and reviewed source file digests. Those three closure fields must equal the generation the reservation itself recorded: `reserve(..., generation=...)` stores the source closure of the acquiring campaign on the row, and the abort is refused unless the caller proves that same closure. The closure that retires a row is the row's, never the aborting code's. Sources move on, and a fix to this file changes the current closure while a held row keeps naming the closure its acquisition ran under, so an abort that had to prove its own closure would be unretirable by construction. What the caller presents instead is that run's own `receipt.json`, which recorded the generation at acquisition time; when the row records a generation, the receipt must name the same one. What the generation proves is identity, not review: it establishes that the record was built from the run that made the reservation, and nothing about whether those sources were reviewed. Re-reading each closure file out of the frozen commit is a separate, independent check and lives in the campaign lane, not here, because this library must not run a subprocess against a caller supplied directory. The independent review of the call graph and the hashes remains a separate obligation. If the persisted receipt records a generation of its own, it must name the same one. A reservation written before this binding existed carries no recorded generation and stays bound to the legacy closure named by `LEGACY_COMMIT_GENERATION`, so the existing `aborted-no-data` history rows still validate while a later generation retires on its own closure. The recorded generation is revalidated on every ledger read. An independent review must verify the call graph and those hashes before a real invocation; the record alone does not establish that unjournaled transport is impossible. No production invocation is part of this library change.

The receipt shape a no-data abort is held to is selected by the receipt kind the reserving Gate plan declares (`receiptKind`, bound to the claim by `gatePlanDigest`), from the closed map `NO_DATA_RECEIPT_SCHEMAS`. A kind outside that map has no retirement contract and is refused rather than read as one of the known shapes. Two shapes are known. `commit-acquisition-receipt-v2`, and `txn-expiry-acquisition-receipt-v1` and `partition-cursor-acquisition-receipt-v1` which project onto the same vocabulary and are mapped to it by name, is the Commit acquisition shape described above: credential items carrying `slot`, `verified` and `status`, the management slot ids in `metadata`, no collection and `productionExecuted` false. `request-bytes-acquisition-receipt-v1` is the request-byte lane's shape: `managementEvidence` rows, one per entry of the Gate's `managementUsed` and in that order, each holding the bounded response the Gate charged, whose digest must equal the Gate event's `responseDigest` and whose body digest the event's `bodyDigest`; `credentialEvidence` holding the `request-byte-token-attestation-v1` body of every credential slot that completed, and nothing else; `metadata` as the data route journal, one row per Gate data event with the event's status and response digest, so `productionExecuted` is true exactly when ownership reads were sent; and `mayHaveCreated` false. A stop may fall before the first management slot, inside the management sequence, or during the non-creating reads; each leaves a prefix of the declared observation slots and the receipt must reproduce that prefix. Neither shape decides whether data was written: that is settled from the registered Gate's journal, by `_no_data_gate` here and again by the Gate's own `abort_no_data` under its lock, so a receipt cannot claim more or less than the Gate shows. A receipt that records a `gateDigest` must record the one the record binds.

For the Commit shape the receipt must bind the same ticket, failed production acquisition, four charged management calls, two reaped credential workers, two metadata receipts, and no collection or production wire execution. Under the Gate lock, the transition checks its empty data journal, zero job counters, no inflight, owned, creation, absence or capture state, exact management journal and accounting, and positive registered coordinator/job PIDs that are no longer present. Missing worker identities refuse the transition even when the receipt and Gate digests agree. A missing Gate or receipt also refuses it. The Gate is then stopped for all claim, management, data, recovery and normal completion paths, including recovery management through `ProductionGate.manage()`. Ledger first persists `closing` with the abort record digest, then persists `aborted-no-data` only after checking a fresh terminal Gate digest. A crash at `closing` or after the Gate stop can resume only with the same record. Only conflict locks and concurrency become available again; the allocation, nonce, claim, ticket, Gate path and audit row remain charged and nonreusable. This state proves no data dispatch, not absence of either Firestore document, and never marks normal cleanup, acquisition validation or promotion readiness.

`close_after_escalation(ticket, record)` is the terminal transition for a stop that cannot prove nothing was written. A Commit whose receipt was lost may have been applied, so such a reservation is correctly refused by the no-data path; holding it while the residue is unresolved is right, but without this there was no exit afterwards and the row stayed active forever, keeping its lock key and its whole allocation even once the owner had removed the residue by hand.

The two exits are disjoint by evidence, not merely by record shape. A receipt whose Gate proves no data was written is refused here and must use `abort_no_data`; a receipt that does not is refused there. Neither can be mistaken for the other, and this transition never asserts that nothing was written, only that nothing remains.

The record has the closed kind `shared-owner-escalation-close-v1` and binds the exact ticket, the persisted `receipt.json` and its digest, the Gate digest, an owner attestation and a typed absence proof for every owned resource the Gate plan names. The attestation is a closed seventeen-field `owner-escalation-attestation-v1` bound to this campaign, nonce, claim, reservation, receipt, Gate, ledger root and execution host, carrying the owner and recovery identities, the resource count and the digest of the resource list, and a freshness window of at most 24 hours. A placeholder-shaped owner identity is refused. Every absence proof must be a typed Firestore `NOT_FOUND`, so a 200, an untyped 404 or a missing resource all refuse the transition.

The transition also requires what the no-data abort requires of the environment: the recorded coordinator and job workers must be proven exited, the registered Gate path must be unchanged, and the live Gate must still digest to the value the receipt records, so a Gate that moved after the receipt was written cannot be closed against it.

**Operator procedure.** Remove the residue by hand under the owned scope, then read back every resource the Gate plan names and keep the typed `NOT_FOUND` response for each. Write the attestation against the reservation's own claim, nonce and receipt, within its freshness window, on the host that will perform the close. Call `close_after_escalation` with that record. The result is the terminal state `closed-after-escalation`: the reservation stops being active and its conflict lock becomes available, while its allocation, nonce, claim, ticket, Gate path and audit row remain charged and nonreusable, exactly as for a release or a no-data abort. The row is not evidence that no document was ever written, and must never be read as such.

This cleanup check does not validate the final production comparison, owner approval provenance, artifact build, metadata/configuration equivalence, or receipt completeness. Those remain the outer runner's responsibility. Historical approvals and observation receipts are not rewritten by ledger updates.

## Limits integration

`fs-write-limits/production_bridge.py` provides `ReservedCoordinator` and `bind_reserved_wire`. The Coordinator freezes the ledger identity and ticket as well as verifying the exact registered Gate; replacement of those bindings is refused; management attempts validate the shared lease after the existing rate wait and durable attempt accounting. Data sends validate it inside the Gate callback after its rate wait. The reservation implementation is included in the collector source digest. The production entrypoint must use this reserved variant, the fixed wire transport, and a canonical shared ledger; the lower-level unreserved bridge remains an internal component and test surface, not production admission.

Focused tests use actual files, spawned processes, Gate accounting and synthetic bounded transport responses. They cover atomic contention, ancestor conflicts, permission-envelope reuse, nonce reuse, expiry, worker interruption, complete cleanup, closing-state refusal and lock ordering. No test in this directory acquires credentials or sends a production request.
