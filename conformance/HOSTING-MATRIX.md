# Hosting compatibility matrix

Hosting is a new implementation surface. Its parent is `COMPAT_VERIFIED` (closure review of 2026-11-11, `spec/compatibility/closure/HOSTING.json`). The Production column below is the strict profile compared with four production recordings on preview channels: two of the parent corpus (runs 658bb2 and 9a8d57, 201 requests each) and two of the follow-up corpus (runs 11ae6c and 1c6a4c, 78 requests each): `Recorded` means the strict profile under `productionExact` answers every recorded request of the condition as production did, apart from the known differences listed after the table. The official-emulator columns describe the `emulator` profile only. The fixture manifest closes the HTTP configuration, public file and glob inputs. Each test condition reads those fixtures.

The offline oracle is firebase-tools 15.28.2 and its locked superstatic dependency. The harness invokes the actual strict middleware stack, Hosting initialization middleware, Functions rewriter and Run rewriter. It supplies synthetic initialization data and registers a loopback Functions endpoint. It does not invoke configuration discovery, read credentials, fetch a web configuration, resolve a production Run URL or allow live Functions fallback. This is an implementation-stack comparison, not a claim that the full Firebase CLI has been exercised.

The production observation is recorded: its recorder, corpus, judge and comparison tools are in `conformance/src/hosting-production/`, the four masked recordings and the six comparisons are `conformance/hosting-production-pass-1.json`, `-pass-2.json`, `hosting-production-followup-1.json`, `-followup-2.json`, `hosting-production-run-comparison.json`, `hosting-production-strict-vs-pass-1.json`, `-pass-2.json`, `hosting-followup-run-comparison.json` and `hosting-followup-strict-vs-run-1.json`, `-run-2.json`, and `spec/compatibility/closure/HOSTING.json` lists the conditions, the known differences and the limitations. Of the 201 rows of each parent strict comparison 18 carry a known difference, and of the 78 rows of each follow-up strict comparison 42 (`KNOWN_DIFFERENCE`, never counted as a match). The recordings were made on preview channels, never on the live channel; function and Run rewrites are excluded by owner decision (ledger 2435), and `ignore` and the local safety properties are not observable in production.

The generated PICT cases are materialized in the shared corpus, including the mandatory seed combinations. The property corpus uses the pinned official matcher; it is not a second hand-written matcher used as an oracle. Official observations must be generated inside an inspected network-none container with a separate empty home directory. Each run also records an external literal-address connection refusal. Raw traversal requests use `http.request` with the literal request target rather than a URL constructor that might remove dot segments.

Known differences that the strict profile does not reproduce: Brotli encoding (KD-COMPRESSION, KD-BROTLI), the length of the gzip body of a file of 100 to 1,500 bytes (KD-GZIP-LENGTH, ruling 27: bounded at 8 bytes, same decoded body, both gzip), the hosted SDK files, the `init.json` layout beyond `apiKey` and `projectId` and the length of `init.json` and `init.js`, and the `Location` host of the 302 production answers to a request with dot segments (an internal host that changes per request; the path is compared). Strict-transport-security and x-robots-tag are excluded as edge-set headers. The bodies of the default 404 page and of the hosted auth handler page are known differences (KD-DEFAULT-404-BODY, KD-AUTH-HANDLER-PAGE): their bytes are not shipped (owner decision of 2026-11-11), so strict serves pages written for fireemu with production's status and headers. Still outstanding: routing to real Functions/Run resources, deployment metadata, and every request outside the 279 of the two corpora. The `emulator` profile makes no production claim: against the recordings it differs on 197 of 201 rows. A version's `fileCount` is a string in the public API schema, not proof that it equals the number of uploaded user files.

Agreement is limited to the committed `official.json` and `official-globs.json` observations and selected response headers. Initialization JavaScript is compared by its `initializeApp` effects, not source text. Dynamic Date headers and ephemeral ports are excluded. Missing local upstreams and external SDK resources fail locally without production fallback; this boundary is not an approved equivalence to production. Capability confinement rejects escaping links and malformed private paths even where upstream permissiveness has not been measured.

Filesystem tests cover retained-handle replacement, relative symlinks, escape rejection, FIFO refusal and bounded large-file streaming on Linux. Windows uses the same capability API and includes native symlink/junction tests, but no native Windows result is available from this task. This is not a cross-platform parity claim. The root capability confines name resolution; it does not freeze file contents against concurrent writes or treat administrator-created hard links and mounts as untrusted pathname input.

The original differential uses an initialization stub. The separate `regressions.mjs` suite loads the pinned real compat Auth SDK, executes the served initialization script, checks the selected emulator address, and performs anonymous sign-in with observed loopback-only requests. Init JSON and JS share a synthetic nonsecret `fireemu-local-only` API key; this enables offline SDK initialization and is not a production credential or a fetched web configuration. Lifecycle tests cover normal shutdown and failed startup; cancellation during an active file hash, slow upstream response or incomplete upload remains untested. Response trailers and hop-by-hop header edge cases also remain outside the finite corpus. No Windows cross-compilation was performed in this task.

The redirect edge fixture records the actual pinned middleware outputs for captured backslashes, control characters, Unicode, literal colons, percent encoding, query strings and fixed external destinations. Live HTTP tests compare `Location` and browser URL authority, including the control-stripping attack `/:name/evil.example` with a tab capture. Configured redirects serialize the decoded value once; canonical asset redirects retain their original encoded path.

Two differences of the emulator profile are explicit (the strict profile follows the recording instead, see above). Supported reserved initialization and offline SDK routes precede configured redirects according to [Firebase Hosting response priority](https://firebase.google.com/docs/hosting/full-config#hosting_priority_order); the pinned local middleware returns 302 for the recorded catch-all cases. A malformed percent escape in a matching redirect query returns 400 without terminating fireemu; the pinned middleware instead terminates with an uncaught URIError. Neither difference is claimed as an observed production result. Hosting address validation applies only when Hosting is selected; selecting Hosting still rejects unapproved nonloopback bindings. A run that does not name Hosting in `--only` keeps starting when its Hosting entry is unsupported (several sites, no `public`, an address fireemu refuses, a regex it cannot compile): the entry is reported as a notice and Hosting is not started. As in firebase-tools 15.28.2, a missing public directory still starts and answers 404, and a busy default port moves up (never onto 5001) while a configured port stays fixed.

Captured segments must be nonempty. Fixed HTTP(S) and protocol-relative authorities are separated before substitution, so literal ports and IPv6 colons cannot be mistaken for capture names. Captures are accepted only in the remaining path/query suffix; unsupported dynamic authority/scheme templates and captures before the first slash of a rootless destination do not produce redirects. Static rootless destinations and `folder/:name` remain supported. The edge fixture keeps the pinned middleware's unsafe numeric-port substitutions and scheme-template outputs alongside explicit safe local expectations; valid fixed IPv6 authorities also intentionally differ from its invalid encoded-bracket output. These observations are not normalized into agreement.

Run `node conformance/src/hosting/regressions.mjs <fireemu-binary>` inside the inspected offline environment to exercise the real SDK and raw-target edge fixtures. Its deterministic generated-input property parses actual HTTP `Location` values and checks the configured origin, including an explicit empty-capture rejection obligation.
