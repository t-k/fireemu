## Start in one command

Node.js 20 or newer is required. Fireemu is published on npm as [`fireemu`](https://www.npmjs.com/package/fireemu).

```sh
npm install --save-dev fireemu
npx fireemu init

# Run your tests against the emulators, then stop them
npx fireemu exec -- npm test
```

`fireemu exec` starts the emulators, sets the Firebase SDK emulator environment variables for your command, and exits with its status. `fireemu up` keeps them running with the Emulator UI at `http://127.0.0.1:4000/ui/`.

## Why Fireemu

<CardGrid>
	<Card title="Behaves like production" icon="approve-check">
		Under the recommended `strict` profile, a query with no composite index fails as it does in production, with the same error. The few [development defaults](guides/profiles/#where-fireemu-departs-from-production-on-purpose) are documented and can each be switched.
	</Card>
	<Card title="Verified against real Firebase" icon="magnifier">
		<VerifiedAreaCount /> areas, from Firestore transactions to Storage Security Rules, are compared with recordings from real Firebase projects.
	</Card>
	<Card title="Built for tests" icon="puzzle">
		TOTP multi-factor authentication and App Check, which the official emulator lacks, a virtual clock for scheduled functions, and Security Rules denials that show each evaluated condition.
	</Card>
	<Card title="Fast and light" icon="rocket">
		A single native binary. In one benchmark run it started 21.6x faster than the official Firestore emulator and used about 1/34th of its idle memory ([details](compatibility/performance/)).
	</Card>
</CardGrid>

## Supported products

| Product | Status | What you can test |
|---|---|---|
| [Cloud Firestore](products/firestore/) | Supported | Standard and Enterprise editions, composite index validation, Security Rules |
| [Firebase Authentication](products/auth/) (Identity Platform) | Supported | Sign-in methods, TOTP and SMS MFA, multi-tenancy, OIDC and SAML providers, blocking functions |
| [Cloud Storage for Firebase](products/storage/) | Supported | Firebase and JSON APIs, Security Rules |
| [Cloud Functions for Firebase](products/functions/) | Supported | HTTP, callable, event, scheduled, task queue and blocking functions, from Node.js codebases and, on macOS and Linux, [Python codebases](products/functions-python/) |
| [Cloud Pub/Sub, Eventarc](products/pubsub-eventarc/), Cloud Tasks | Supported | Topics, subscriptions, push and pull delivery, custom events, task queues |
| [Firebase App Check](products/app-check/) | Local testing | Debug tokens |
| [Firebase Realtime Database](products/realtime-database/) | Partially supported | REST, realtime protocol, Security Rules, export and import, Functions triggers; verified against production for the recorded cases |
| [Firebase Hosting](products/hosting/) | Partially supported | Served without a production parity claim yet: one `firebase.json` site: static files, redirects, rewrites (including to local functions), headers, clean URLs, localization |
| App Hosting, Data Connect | Not yet supported | |
| Firebase Extensions | Not planned | |

Known gaps are listed in [Limitations](compatibility/limitations/). The [compatibility tables](compatibility/) show the production verification status of each area.
