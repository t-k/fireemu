# AUTH-MFA preparation

Two packages live here, both `productionExecuted=false`.

`AUTH-MFA-AGE-TOTP-01` is the prepared successor campaign for the AUTH-MFA row: pending-credential age causality with fresh same-account controls at 300, 450 and 600 seconds and an already-refused 1800-second control for the refusal direction, a TOTP enrollment, sign-in and withdrawal matrix computed from locally derived RFC 6238 codes, an enrollment-session age family, and an interaction matrix. `mfa_cases.py` holds the thirty-three observation cases with their expected local results and their due offsets, `mfa_manifest.py` the frozen manifest with enforced limits, the permission envelope and the owner preconditions, `mfa_collector.py` the bounded resumable state machine, `mfa_provenance.py` the recomputed source binding, `mfa_comparator.py` the comparison contract and `mfa_local_shadow.py` the owned local run. The design, the budget and the limits of the campaign are in [the campaign document](../../../docs/compatibility/auth-mfa-next-campaign-preparation.md); the frozen manifest is checked in at `spec/compatibility/broad-runs/o2-mfa-next-campaign-manifest.json` and the local ledger at `spec/compatibility/broad-runs/o2-mfa-local-shadow.json`.

The collector never sleeps. A step that must wait returns the instant it becomes due, and a checkpoint file carries the run across processes. Budgets are enforced against the transport's real call count, not one notional call per case: an exceeded request or wall-clock budget latches an abort, and an aborted run still has to prove its cleanup. Both the observation the collector stores and the row that is published are screened for secret or credential material before they are written.

Every aged resource is acquired at one common origin, so the ages elapse concurrently and the critical path is the largest age rather than their sum. The manifest declares that schedule and every case's due offset; the serial reading costs 10830 seconds and does not fit the budget, which a collector test demonstrates in both directions.

The provenance binding is recomputed from the worktree rather than read from the receipt, which is the gap the earlier review named. It covers every non-test module in the package, the recorder that issues the requests included, and a test fails if a new module is added without binding it. A receipt also carries the manifest it ran, which the comparator recompiles before comparing anything. Agreement additionally requires a production side that says it was executed and carries owner approval bound to that receipt's own manifest and nonce digests. No preparation receipt can reach `MATCH`.

`AUTH-MFA-TOTP-ENROLL-RETRY-01` remains the earlier non-executable preparation. Status: `PREPARATION`. It has no production transport, no observed production receipt and no parity claim; its manifest is a logical sequence rather than an executable request plan, its proposed limits are not enforced, and its comparator returns `INDETERMINATE` for every supplied pair because caller-provided hashes cannot establish provenance. Its one distinct obligation, whether a wrong TOTP code leaves the same enrollment session usable for one correct retry and whether replay after success is refused, is carried forward as cases in the campaign above. Related controls in `conformance/fixtures/auth/mfa-error-shapes.json`, `conformance/fixtures/auth/mfa-enrollment-eligibility.json` and `conformance/src/auth-probe/programs.mjs` do not discharge it.

## O8 descriptor, admission and launcher

`mfa_descriptor.py` declares the campaign to the shared O8 core (`tools/compat-broad/o8-core`): schema kinds, the 2700 s window plus 300 s recovery, the source map over the whole lane and the shared closure, the plan reference that recompiles to one manifest, the budget re-derived slot by slot (160 data, 21 management, 33 recovery, 186 headroom against the 400 bound), the Ledger lock scopes (WRITE on the nonce-scoped account namespace, EXCLUSIVE on `project/fireemu-35fe6/auth/config`, READ on identity) and the cost model (US$0.10 estimate plus one micro-USD per management slot, US$0.50 ceiling). Production time is wall-clock time: `descriptor()` refuses any sleeper but `mfa_timing.WallClockSleeper`, and a plan reference carries its timing mode so a rehearsal's frozen inputs cannot be launched against production. `rehearsal_descriptor()` is the only way a virtual clock enters a descriptor.

`mfa_config_lock.py` models the project configuration change (MFA `ENABLED` with TOTP and phone, the test phone number, SMS regions allow-by-default) as a locked step: the readback at preflight must equal the owner-frozen `authConfigBaselineDigest` or the run refuses to start; the pre-value is saved in the private run directory before the change is attempted, the receipt carries only its digest and a redacted reference; the change is verified by readback; the pre-value is restored and verified at the end and on every stop path, exact or under a documented normalization of the masked fields, and the receipt records the status.

`mfa_walk.py` is the resumable walk over the thirty-three cases, `mfa_production_transport.py` the production session over the shared wire worker and the private credential handoff (bearer token with `roles/firebaseauth.admin` and the Web API key, verified through tokeninfo against the frozen principal), `mfa_admission.py` the file-bound admission with the receipt screen and the hosting check, `mfa_production.py` the run driver and `mfa_o8.py` the launcher (`--resume` continues a stopped run under the same reservation, `--abandon` deletes everything it owns and restores). Exit 0 requires every case resolved, every account proven absent, the restore verified and the Ledger released; exit 1 means the run started and did not complete, the reservation is held and a receipt was written; exit 2 means admission refused before anything was reserved or read.

**Hosting.** `mfa_gate.py` projects the walk onto the shared Gate the way the credential lane does: every request is a frozen slot with `$binding:` placeholders resolved from this run's own responses (bound values live in a private `gate-bindings.json`, never in the journal), the two account cleanup routes are the job's resources, and the accounts and the configuration lock are named beside them as `projects/fireemu-35fe6/auth/accounts/<campaign id>` and `projects/fireemu-35fe6/auth/config`. The facade settles creation for accounts, records typed deletion and absence per account, and journals two zero-wire skips: a finalize behind a refused start, and the cleanup of an account that was never created. The rehearsal (`test_mfa_production.py`) runs the whole state machine on the shared Gate, at its 1200 s wall cap under a virtual clock: 93 observation slots, 32 recovery slots, six management slots, `Gate.finish` accepted, and the shared Ledger's own refusal of the reservation recorded by name (`canonical Firestore resource required`). The production claim is additionally refused for its 2700 s duration and wall. `mfa_admission.hosting_check` names every refusal (`ledger-claim-refused`, `gate-wall-cap`, `ledger-resource-refused`) and the launcher exits 2 with `HostingRefused` before any credential is read. What the shared change has to provide is written up in the campaign log (`shared-auth-scope-proposal-mfa`). A paused run keeps its configuration applied under the held exclusive lock, because the Gate admits the restore only after the recovery slots; every terminal path restores.

**Recovery procedure.** A run that stopped (exit 1) is either resumed or abandoned from a new process, which first adopts the shared Gate (`MfaGate.adopt`: admitted only when the recorded processes are gone, nothing is in flight and the Gate's monotonic clock still runs forward, i.e. the same boot; refused by name, `GateAdoptionRefused`, before any credential is read). Signups an earlier process sent without recording an answer are settled by an owner readback of the role's nonce-derived address (`recover:address-lookup`, journaled as not charged by the Gate): present means the account is adopted and deleted with the others, absent means the signup never applied; the anonymous role has no address and is reported as `untrackedIntents` for the owner to find. A restore the Gate's one-shot slot could not take (a transient PATCH failure, a death between the apply and its readback) is retried outside the Gate (`recover:auth-config-restore`, at most two attempts, journaled as not charged by the Gate) and verified by readback. Late recovery: the shared core binds every launch to an approval window of `window_seconds` (3000 s), so an abandon after the original window needs a re-minted approval with the same `inputsDigest`, `permissionDigest`, `sourceCommit`, `artifactSha256`, `planDigest`, `nonceDigest`, `launcherSha256` and `artifactProfile`, and `windowStartsAt <= now`, `windowExpiresAt >= now + 3000` even though the recovery itself needs the 300 s reserve; the reservation deadline is not consulted by `--abandon`.

**Limits of recovery.** (1) A request the dead process left in flight is settled on adoption once the recorded processes are proven gone: a creating slot becomes `unknown` and is discovered by the address readback, any other slot is recorded as interrupted; adoption while the recorded process is alive is refused. (2) The same-boot check (`started`/`lastSent` below `time.monotonic()`) is necessary, not sufficient: a reboot whose uptime already exceeds the previous one passes it, and the Gate's phase deadline is then the backstop that refuses every dispatch, so a run adopted after a reboot fails closed and the owner recovers from the lock record and the intents journal by hand (restore: PATCH `admin/v2/projects/fireemu-35fe6/config?updateMask=mfa,signIn.phoneNumber,smsRegionConfig` with `mfa_config_lock.restore_patch(config-baseline.json)` and compare the readback; accounts: `accounts:lookup` by each `o2-mfa-<role>-<nonce>@example.com` address, delete, read back). (3) The anonymous role (`interaction-anonymous`) signs up without an address; if its signup was sent and its answer lost, no readback can find it and the receipt reports it as `untrackedIntents` (never cleanup-complete, never no-data). Owner procedure: list the project's accounts (`accounts:batchGet`, the oracle project is small) and delete the one with no `email`, no `providerUserInfo` and a `createdAt` inside the run window recorded in the receipt; an admin-created anonymous account with a pre-chosen `localId` would remove the residue but yields no anonymous sign-in session, so the case would no longer exercise the ineligible first factor. The Gate's ledger and the walk's are reconciled before every cleanup (`reconcile_gate_accounts`), and a stop is classified `abandoned-cleanup-complete` only when the Gate's finish agrees with the walk's cleanup.

**Resume and abandon.** A resumed or abandoned process reads the earlier process's checkpoint, material and lock record before it sends anything, so a receipt written on a failure before it can act still names what is owned and is never retirable as no-data. `--resume` is admitted only while the original reservation holds the critical path that is left plus the recovery reserve (`mfa_production.remaining_seconds`), and the resume allowance counts attempts, not time. `--abandon` is recovery only: it does not consult the reservation deadline or the hosting check, restores the configuration through the Gate's recovery slots and deletes every owned account; it needs an approval whose window is open, which the owner re-mints for a late recovery (the shared core binds the window to the whole campaign, see the proposal). The bearer is verified against the frozen principal again on every resume or abandon; the shared Gate has no second tokeninfo slot, so that call is counted by the session and recorded as not charged by the Gate. Each aged resource records its own acquisition instant and every aged row is scheduled and reported from it: rows carry `observedAgeSeconds` next to the target age. A stop request is honoured during a wait, at the next five-second slice.

The versioned local shadow the descriptor compares against is `spec/compatibility/broad-runs/auth-totp-enroll-local-shadow-v2.json`; `test_mfa_shadow_binding.py` fails by module name when a bound module changes after the record was taken or when the record's digests differ from its own commit. The historical `o2-mfa-local-shadow.json` is preserved byte for byte.

```sh
uv run --project tools/compat-inventory --locked --python 3.12 pytest -q tools/compat-broad/auth-totp-enroll
uv run --project tools/compat-inventory --locked --python 3.12 \
  tools/compat-broad/auth-totp-enroll/mfa_local_shadow.py --output /absolute/private/o2-mfa-shadow
```

The local run owns one strict Auth artifact on OS-assigned ports, ages by advancing that instance's virtual clock, deletes every account it created, confirms absence, and reaps the child process. It contacts nothing but loopback and reads no ambient Google credentials.
