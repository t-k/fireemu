# Production-derived resource-name regression

This supplementary release regression covers only `resource-names/invalid-name` and `resource-names/reserved-prefix`. It preserves every admitted REST/gRPC witness in O1 and O2: invalid-name steps 03, 06 and 07; reserved-prefix steps 02 and 09. It does not settle the complete 122-case private qualification or promote PUBSUB compatibility.

`conformance/pubsub-resource-names-production.json` retains the original capture digest, line and exchange number for each selected request and response. O1 originates from `capture-148026092d56.jsonl` (SHA-256 `3223cdb44dc32ab866377f9532cf4c917cb45f73cfaa9f53a162e4466ac9f57d`); O2 originates from `capture-a8ed1cce53f0.jsonl` (`fc59ae358f0140e322f8fd70b2b0acdc9c1cd1ce9ebc6e41e3d318a94b64ca87`). Project identifiers are consistently replaced with `demo-pubsub-release`. Resource IDs, percent encoding, response fields, status codes and error details are retained. The fixture's harness digests bind the public projection/replay interpretation, not the historical recorder's source identity.

The REST invalid-character request contains `bad%24character-r` and was accepted with status 200; the native request contains `bad$character-g` and was refused with INVALID_ARGUMENT. The adapter preserves that difference. Each transport's recorded step-01 topic creation supplies the subscription request's dependency. Only positively confirmed own creations are deleted, once each; an unknown response stops dispatch and cannot become successful cleanup.

The historical REST captures have no response bodyBytes/contentLength. The existing strict judge therefore retains NOT_COMPARABLE for otherwise equal REST rows, with `recorded wire length missing`. No wire length is reconstructed from serialized JSON. Status/body changes still become DIVERGES before that missing-length check; the release gate compares the exported actual responses exactly, so the NC reason cannot hide a different body. Native details and all observed response fields remain strictly compared.

R21 uses the installed binary for two separate `exec` sessions and then exports the combined 20 rows. It hashes that actual binary before and after each session and again during export; no final-artifact labels or provenance from another binary are transferred. Existing release supervision gives each session a 180-second limit. Requests have 5-second deadlines and a closed local bound of 24 per observation (12 recorded setup/selected calls plus at most 12 own cleanup calls). The observed-source path uses 15 calls per observation, 30 total. There are no production calls, credentials or unbounded retries.

The full private two-pass qualification remains a separate gate. Existing GET/N13 debts and unobserved wire evidence are not waived by this subset. A genuine release build pin remains necessary for private lane replay through the installed-build-pin bridge; this regression does not invent that provenance.
