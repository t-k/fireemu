# Pub/Sub authentication on the local endpoint

This contract is defined before implementing authentication admission. It applies to the loopback Pub/Sub endpoint in the strict profile, including REST, native gRPC and opening StreamingPull.

An entirely absent Authorization header is accepted. This is an explicit production divergence for clients using `PUBSUB_EMULATOR_HOST`, rather than a claim that production permits anonymous requests. The Node Pub/Sub SDK selects insecure channel credentials for an emulator endpoint in [`determineBaseUrl_`](https://github.com/googleapis/google-cloud-node/blob/pubsub-v5.3.1/handwritten/pubsub/src/pubsub.ts). In the published `@google-cloud/pubsub` 5.3.1 source this is `build/src/pubsub.js:366–372`. The published `google-gax` 5.0.8 source, `build/src/grpc.js:184–186`, returns those explicit credentials before attaching the Google credential metadata generator at lines 192–202. Consequently this SDK path does not add an Authorization header. These versioned package sources can be read without loading client credentials.

Header presence is the exact boundary: empty values, whitespace, unsupported schemes, `Bearer owner`, opaque values, unsigned JWTs, altered JWTs and duplicate headers are present credentials, never anonymous requests. No trimming, token parsing failure or duplicate selection widens the headerless exception. The emulator profile retains its existing credential-independent behavior.

Local verification currently has no configured Google OAuth issuer, trusted signing keys, token introspection service or accepted credential type. Its supported credential set is therefore empty. Every presented credential fails local verification as unsupported; no credential contents are decoded or treated as an identity. In particular, structurally plausible tokens and Firebase ID tokens do not prove Pub/Sub OAuth authentication. This limitation also rejects valid production OAuth credentials on the local endpoint. Such credentials must not be described as invalid in production, and their production behavior remains unobserved here. Supporting a nonempty credential set requires a separate explicit trust contract and cryptographic verification; it must never fall back to anonymous access.

A failed local verification produces HTTP 401 with `UNAUTHENTICATED` on REST, or native gRPC code 16 with the same recorded authentication message. The recorded REST GetTopic, CreateTopic and Publish envelopes include `google.rpc.ErrorInfo`, reason `CREDENTIALS_MISSING`, service `pubsub.googleapis.com` and their respective Publisher method. These shapes are grounded in the production authentication observations for those three operations. Exact byte layout and other credential/method combinations are not claimed as production observations.

Admission occurs before REST JSON parsing, gRPC message decoding or broker mutation. A rejected create or publish cannot change resources, advance message identities or publish an event. Tests cover both profiles, headerless requests, immediately adjacent present-header shapes, duplicate headers, the three recorded envelopes, native StreamingPull and a state reference model across accepted and rejected operations.
