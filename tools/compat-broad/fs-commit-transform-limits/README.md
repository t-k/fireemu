# O3 Commit transform limit compiler

This directory contains a credential-free compiler, semantic comparison contract, and owned local-artifact collector for `FS-DATA-WRITE-COMMIT-TRANSFORMS-03`. The compiler and comparator are offline. The collector connects only to its owned loopback runtime; it does not acquire production credentials, create a production Gate, execute production requests, or grant compatibility approval.

`transform_compiler.py` emits two nonce-scoped owned document resources and 17 ordered data operations. The observation sequence creates both documents, submits exactly 500 transforms to one document as two writes of 250 each, submits exactly 501 transforms to the other as writes of 250 and 251, and verifies accepted and unchanged post-state. Six recovery operations read ownership, perform version-bound conditional deletes, and prove typed absence. The compiler does not encode a 500-operation-per-Commit limit.

`transform_comparator.py` validates compiler-plan binding, exact request journals, typed boundary outcomes, transformed fields, unchanged negative post-state, and cleanup version/marker binding. Requests are compared to their own compiler plan before any normalization, including JSON scalar types. Resolved cleanup requests must use the exact relative path and one encoded update-time predicate. It validates calendar timestamps and version relations from creation through baseline, accepted Commit write results, rejected Commit readback, control readback, and recovery. Per-resource timestamp relation signatures retain equality and ordering across all declared metadata slots without comparing absolute clock values. Readbacks bind to the final write result, and commitTime may be later than that updateTime. It normalizes only declared metadata timestamps and resource/owner identity slots using an internal tagged projection; nested user fields and error details remain exact. A typed absence response is the one error whose message carries identity: production and a local reference always run under different projects and nonces, so the resource name embedded in the `NOT_FOUND` message is replaced by the same identity label the `name` slot uses. Only that one substring is replaced; the rest of the message is still compared literally, and a message naming no declared resource is not normalized at all, so different wording remains a `SEMANTIC_MISMATCH`. Both complete journals are shape-validated before semantic classification. Invalid or incomplete journals are `INDETERMINATE`; complete journals with an unexpected typed response or post-state difference are `SEMANTIC_MISMATCH`. It always reports acquisition and promotion as false.

`owned_transform_runner.py` verifies the retained build against runtime inputs reconstructed from the fixed Git tree, copies the executable into an exclusively created private directory, and launches that verified copy under the existing owned supervisor. `local_transport.py` bounds loopback requests and responses. `local_collector.py` preserves all 17 request/receipt pairs, continues complete semantic failures, and retains cleanup responsibility for ambiguous creates. Cleanup requires resource ownership and current version evidence; malformed or incomplete absence responses cannot establish completion. `local_store_fixture.py` is test-only. Local acquisition and promotion flags remain false.

The fixed `006df2e0c` owned run completed 11 observation and six recovery requests against retained runtime `cce4a4f9b`, verified typed absence for both resources, and stopped its process and listeners. Independent review approved the runner after provenance and executable-replacement regressions were addressed. These are local results, not production observations.

`commit_production_bridge.py` regenerates the canonical compiler plan before binding each request, including every embedded Commit transform target. It preserves complete semantic HTTP errors and separates incomplete transport failures. `gate_adapter.py` connects those operations to the existing charged shared Gate callback. Cleanup requires the original conditional-create proof, an exact nonce-bound ownership marker, and a valid current UTC timestamp; unexpected semantic field changes do not by themselves prevent owned cleanup. Typed final absence remains required before resource responsibility can be released.

`commit_production.py` connects all 11 observation and six recovery operations to the Gate. Complete semantic errors remain in the journal. A receipt persistence failure stops observation but still attempts safely owned recovery; incomplete recording prevents final ownership release. Receipt publication uses an fsynced temporary file and atomic no-replace linking so a concurrent destination cannot be overwritten. Independent review approved this collector and the dependency-origin checks; integration at `0042b0725` passed 125 combined Commit and real Limits transport tests.

`commit_acquisition.py` now provides an internal file-bound acquisition function. `freeze_inputs(permission_path, plan, source_root=..., artifact_path=...)` reads the independently supplied owner permission, verifies a clean Git snapshot and the complete supported source map, checks retained artifact bytes, and freezes those bindings. `run_acquisition` requires the permission file, source snapshot, artifact, pre-existing canonical shared Ledger root, API key, explicit private credential handoff and exactly one of two mutually exclusive transports: an O7-issued `ProductionWireCapability`, or an `injected_transport` callable for the local preparation mode. A raw callable can never be the production authority: the injected mode is always recorded as `injected-transport` with `productionExecuted=false` and no worker archive digest, and a callable that names or wraps the fixed wire functions is refused outright. It validates the frozen bindings before reservation, copies the retained comparator and compiler evidence from the verified `source_root` checkout after rechecking their frozen digests, rechecks live permission/source/artifact files before each transport attempt, and verifies them again after postflight. The helper `permission_bindings` describes required fields; it does not create owner authorization or attest who authored a permission file.

`commit_baseline.py` derives the three production values a permission binds but the repository cannot recompute: the Identity Platform configuration digest, the Firestore database projection and its digest, and the pricing location. Each one comes from a named observation record, a recorded production response journal identified by path and by its own SHA-256 plus the line within it, and is recomputed with the same derivation the preflight uses. A baseline value that no recorded observation produces is refused when the campaign is frozen rather than after a preflight spends its budget discovering it, which is what stopped the v10 attempt: its `authConfigDigest` was a literal with no provenance anywhere. A recorded replay has the same line shape, the same routes and the same project as a production journal and sits beside the real logs, so nothing in a journal line tells the two apart. Each observation therefore also names hash-bound run evidence declaring that the responses came off the wire, and a journal under a fixture or replay directory, or outside the recorded production log roots, is refused whatever it contains. A hash-bound journal and a hash-bound live receipt are still not enough on their own, because both can be intact and correctly named while belonging to different runs: an independent review paired a replay journal with an unrelated run's live receipt and the baseline was accepted with every digest correct. Each observation is therefore bound to the run that produced it. The acquisition receipt already records, per phase and privileged route, the digest of the response that run received, and a journal line is accepted only when its response digest appears in that record under the observation phase and the same route, so a journal the named live run did not produce is refused. A recovery-phase response the same run received is refused as well: a baseline is the state before the campaign acted, and a run whose recovery response differed from its observation would otherwise bind a value the next preflight can never match. Two runs that received byte-identical responses stay indistinguishable, deliberately: the value derived from either is the one the named live run observed. The permission carries a `baselineProvenance` block naming the route and journal digest behind each value, and that block is required even where the journals themselves are unavailable, such as on the execution host. Reading a journal proves the bound value came from a recorded response; it does not prove the observation was made honestly.

`commit_abort.py` builds the no-data abort record for a held reservation entirely from that run's persisted `receipt.json`, including the source generation the reservation recorded. A row is retired on the closure the row recorded, never on the closure the aborting process is built from: those differ as soon as anything in the closure is fixed, and a fix to the shared Ledger is exactly such a change. `verify_generation_in_commit` is the independent half, re-reading each closure file out of the frozen commit with `git show` and checking the digests the generation names. That git step lives here rather than in the shared Ledger, because the Ledger must not run a subprocess against a caller supplied directory.

`commit_reserved_adapter.py` uses the existing shared Ledger and Coordinator mechanisms with Commit-specific plan and wire bindings. A versioned production Gate plan adds the nonce, permission/source digests, six observation management slots and four recovery metadata slots. The original local 17-call, 120-second recovery and 1,700-microusd Gate plan remains unchanged. The production path starts with an empty credential state, uses fixed-endpoint OAuth preparation under the shared Coordinator management admission, performs four charged preflight metadata calls, collects 11 observations and six recovery slots, then performs four charged postflight metadata calls. It reserves 27 request slots: one bounded OAuth refresh request, one bounded tokeninfo request and 25 data/metadata requests. There is no separate externally preverified-token path and no uncharged refresh. Initial verification must cover the full 1,200-second wall budget; the recovery allocation is 180 seconds. The Commit override never calls gcloud, discovers ADC or refreshes implicitly. It reuses `fs-write-txn/credential_prep.py` fixed-request, response/lifetime and verified-client/scope primitives, with a Commit-specific permission-bound in-memory authorized-user handoff. Both OAuth attempts have secret-free, durable charge and receipt journals; credentials remain in memory.

`production_cost_model()` derives the fixed storage/network allowance from 17 bounded data request/response pairs (2 MiB each direction), ten conservative management request/response pairs (16 KiB/64 KiB), and 64 MiB of document/index storage for one month. The planning ceiling is USD 1 per GiB transferred and per GiB-month stored, plus 100 microusd per charged slot, without free-quota deductions. These are conservative planning assumptions, not current SKU prices; the independently supplied permission must confirm the exact model and tariffs before any execution. The source records the integer-rounded ceiling used by both Gate and Ledger.

The collector consumes one charged Gate callback; the reserved adapter consumes its one-shot, thread/operation-bound wire permit without a second dispatch. It rechecks the shared ticket, permission, source, nonce, API-key binding, verified credential identity and phase deadline before transport. Cleanup journal entries preserve the compiler's `versionFrom` annotation for the unchanged comparator and separately retain the actual resolved `wireRequest` without that annotation.

Publication is a two-record protocol: immutable `receipt.json` is durably published while the reservation is still held. The receipt records the `generation` this run executed under, the source closure derived by `abort_generation` from the frozen inputs, which is also what `Ledger.reserve` stores on the reservation; an abort of that reservation must prove the same closure, and a receipt that names a different one is refused. Proving it shows the abort runs sources identical to the acquisition's, not that they were reviewed. Only complete recording, owned cleanup, successful postflight and publication permit `Ledger.finish`. Immutable `release.json` then links the receipt digest to the actual final reservation. Receipt-path collisions preserve existing bytes and produce `failure.json` while retaining responsibility. An interruption after Ledger release but before release-record publication leaves no valid saved evidence pair; consumers must fail closed and reconcile against the canonical Ledger rather than infer release from the first receipt. The first receipt never claims a future release already happened.

`commit_saved_recompare.recompare_saved(output, reference_path, expected_inputs_digest=..., comparator_root=...)` recompares one saved receipt under a repaired comparator without touching production. It replays `compare_saved` first, so the immutable classification the frozen comparator produced has to reproduce before anything else runs, then executes the repaired comparator on the same plan, saved rows and saved local reference in a separate isolated subprocess. The record it returns carries both classifications and the source digests of both comparators, so a published repaired result always says which bytes produced it. It reads the saved output directory only, and makes no production request.

Those digests are only worth publishing if they are the digests of the bytes that produced the classification, and `comparator_root` need not be a frozen checkout. Every saved input is therefore read exactly once, and the parsed value, the published digest and the executed source all come from that one read; the reference is passed to the child as already-read bytes rather than as a path it opens again. The comparator and the compiler it validates plans against are written into a private snapshot from those same bytes as read-only files, the snapshot is what the subprocess imports and what the record hashes, and the child runs with `-I -S -B` like the lane's production spawns, so neither the environment, nor user site, nor site-packages is on its path and a comparator that grows a new lane import fails to import rather than silently loading it from a directory this run does not hash. `compare_saved` runs before that read and opens the saved records and the reference for itself, and its refusal for an invalid saved directory must reach the caller unchanged, so the pre-image taken ahead of it is only a probe that never raises; comparing the probe with the real read is what closes the window around the validator. At the end every path the run read is compared against its bytes again, covering what `compare_saved` reads as well: the release record, both bounded OAuth charge and receipt journals and every per-row journal, none of whose digests the published record carries but on which the frozen classification depends, witnessed only if they are there because which files a saved directory must contain is `compare_saved`'s question. Anything replaced underneath refuses the whole recompare instead of returning a record whose result and digests describe different bytes. Two limits stand: a file replaced and restored within the run is invisible to a closing byte comparison, which the repaired half survives because the snapshot is what ran while the frozen half has only this detection; and the snapshot directory is owner-writable while the run is in flight even though its files are not.

`compare_saved(output, reference_path, expected_inputs_digest=..., expected_execution_kind=...)` requires an independently retained frozen-input digest, checks that the receipt records the expected execution kind, matching `productionExecuted` flag and a worker archive digest (the default is production, so an injected-transport directory fails closed and local comparison must ask for `injected-transport` explicitly), validates the linked receipt/release pair, both bounded OAuth charge/receipt pairs and every saved data journal row, checks saved compiler/comparator hashes, then executes only those frozen comparator sources in an isolated subprocess. It does not read current owner permission, credentials, retained executable or checkout, and never performs acquisition. It retains `acquisitionValidated=false` and `promotionReady=false` even when semantic comparison matches.

`commit_o8.py` is the production O8 entrypoint. It consumes frozen inputs, a separate mode-600 `commit-o8-approval-v1` O7 approval JSON, a mode-600 `commit-o8-manifest-v1` retained build manifest JSON, the independently supplied `commit-owner-execution-permission-v1`, source checkout, retained artifact, canonical shared Ledger path, output path and a private credential/API-key handoff via `--credential-fd` or a mode-600 `--credential-file`. The approval has exactly the fields `status`, `manifestSha256`, `inputsDigest`, `permissionDigest`, `sourceCommit`, `sourceInputsDigest`, `artifactSha256`, `planDigest`, `nonceDigest`, `ledgerRoot`, `launcherSha256`, `artifactProfile`, `windowStartsAt`, `windowExpiresAt` and `executionHost`; all must match the supplied files, current launcher bytes, canonical Ledger path, active execution window and running host. `executionHost` is the closed pair `platform` (lowercase `platform.system()`) and `machine` (`platform.machine()`) of the host the approval authorizes, so an approval issued for the reviewed macOS host cannot silently authorize a run on another platform whose process supervision is unverified. The only accepted artifact profile is the reviewed `repaired-567565bdd`, and the retained manifest is validated against that profile's registered build command, runtime source tree, input map and artifact bytes. The manifest digest is over its exact file bytes and its `inputsDigest` must match the frozen inputs. The active window must cover the full 1,200-second campaign allocation, including its 180-second recovery allocation. O7 creates these artifacts; O8 never generates them. The CLI validates every binding before reading credentials, reserving, or invoking `run_acquisition` exactly once; there is no metadata-only or injected-transport mode.

After those checks and before the credential handoff is read, the CLI builds the worker archive from exactly the frozen source map with `o8_bundle.build_worker_archive_from_source`, writes it through a construction handle that is closed before the file is unlinked, and reopens it read-only so no writable alias to those bytes survives. `commit_acquisition.issue_production_capability` then runs `validate_o7_admission`, the single shared definition of the complete O7 check set that the CLI itself uses: approval field set and status, manifest kind and digest, every frozen binding digest, the canonical shared Ledger root, the launcher digest, the reviewed artifact profile, the retained artifact, the permission window fields and the active approval window. Issuance is therefore never a weaker gate than the CLI. It returns a one-shot record bound to that campaign, those frozen inputs, that Ledger root, that approval window and those archive bytes; `run_acquisition` admits it by registry identity rather than by shape, so a look-alike object is refused, and spends it before any I/O, so a second presentation, another campaign, a different shared Ledger root and an expired window all fail.

The `launcherSha256` binding covers the launcher that is actually running: `commit_o8` passes its own `__file__` and the shared validator digests that path, never whichever copy sits beside `commit_acquisition.py`. Every worker spawn reaps its child on any exit, including a deadline, a payload the parent cannot write and an interruption, escalating from terminate to kill after a two-second grace.

Archived workers now pin `sys.path` to the verified archive and interpreter-owned standard-library paths. They do not derive a checkout path from `/dev/fd/<n>` (or Linux's `/proc/self/fd` alias), and the archive import-closure regression rejects mutable checkout and temporary-directory entries. The O7 execution host remains platform-bound; a new platform still requires its own archive bootstrap verification before approval.

The capability object is not itself the wire authority, and neither is the archive descriptor. The archive contains only plain repository sources that anyone may rebuild, so the descriptor is an integrity binding that pins which bytes the worker executes; it is not a secret and grants nothing on its own. The actual authority remains the private credential handoff and the shared Ledger reservation. What the capability adds is that a fully admitted O7 approval can be spent exactly once, within its own window and against its own shared Ledger.

`commit_remote_transport.request` is now local only: it requires an explicit loopback origin and cannot reach the fixed production origin at all. Production runs through `request_bound`, which re-verifies the descriptor (regular, unlinked, read-only, unchanged, exact digest) immediately before each spawn and launches `python -I -S -B /dev/fd/<n> --worker <archive sha256>` with `close_fds=True` and only that descriptor in `pass_fds`. The parent copy stays `FD_CLOEXEC`, so no unrelated child inherits it. The archive's fixed `__main__.py` dispatcher accepts only `--worker` and the digest; the child re-verifies its own archive origin and digest before it reads the credential envelope from stdin and again before the bounded exchange. The token travels only on stdin, never in argv or the environment, the child's stdout is bounded and its stderr is never echoed, and a deadline terminates and reaps the worker before a bounded failure is returned. The existing two OAuth charges and four metadata preflight GETs therefore precede data collection, and any drift aborts before the next wire attempt. Public errors and receipts contain only type/status information and never handoff values. The CLI does not create approval, discover ADC or widen budgets.

All current outer tests use whole communication fixtures under real file permission validation, shared Ledger admission, Coordinator charging and Gate/collector execution. Injected callbacks are labeled `injected-transport` with `productionExecuted=false` in internal tests. Production use remains blocked unless an independently reviewed owner permission, real frozen preparation artifact/input digest, canonical shared-root selection, current tariff confirmation and final provenance review are supplied; fixture owner fields grant no such authority.

Run the focused checks with:

```text
uv run --project tools/compat-inventory --locked pytest tools/compat-broad/fs-commit-transform-limits
```

The timestamp contract follows the [Commit response](https://firebase.google.com/docs/firestore/reference/rest/v1/projects.databases.documents/commit) and [WriteResult](https://firebase.google.com/docs/firestore/reference/rest/v1/WriteResult) definitions: write results correspond to request writes, and commitTime bounds when reads can observe their effects; it is not assumed equal to each write updateTime.

## Local O8 lifecycle proof

`test_o8_local_adapter_proof.py` is the non-authorizing preparation proof for this campaign. It uses the existing `injected_transport` mode and the real acquisition path: bounded OAuth preparation fixtures, the reserved Coordinator, the charged Commit Gate, the shared Ledger reservation, the collector, immutable receipt publication and conservative ownership retention. Transform-only Commit writes do not carry an explicit `exists=true` precondition, so an acknowledged response cannot prove that a lost response would not have created a document; the proof therefore expects `releaseEligible: false`, `reservationReleased: false`, and a held reservation. The production transport entry points are replaced with failing sentinels, so a production wire call fails the test immediately.

The proof uses synthetic offline credential and response fixtures. It does not obtain a production credential, contact a production origin, create or change a production resource, or grant compatibility approval. Passing this test establishes only that the local preparation lifecycle is internally complete; it does not establish `productionExecuted`, `acquisitionValidated`, `promotionReady`, or production compatibility.

Run it with:

```text
uv run --project tools/compat-inventory --locked pytest tools/compat-broad/fs-commit-transform-limits/test_o8_local_adapter_proof.py
```
