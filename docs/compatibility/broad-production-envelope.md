# Proposed broad production execution envelope

Status: proposal only. No execution permission, result approval or revision-3 authorization is implied. The current milestone performs local execution only. A future owner approval must name the final frozen observer/manifest hash and the fields below; technical AI review is recorded separately.

Target: project fireemu-35fe6, expected project number592603257417. Firestore database(default), Native Standard only, existing approved location/configuration read back before writes. Enterprise, MongoDB and any additional database are outside this envelope. Abort if project number, edition, database identity or required baseline differs.

Permitted operations: Identity Toolkit password/anonymous signUp, signInWithPassword, account lookup/update/delete and Secure Token refresh; privileged account reads/updates/deletes only for run-owned UID/email pairs after marker verification. Firestore get/create/patch/delete, batchGet, runQuery, runAggregationQuery, beginTransaction/commit/rollback and batchWrite, restricted to the run's owned collection/document namespace. No IAM, IdP, tenant, custom-token signing, project config, blocking function, MFA, OOB, SMS, email delivery, Rules, index, backup, database lifecycle, import/export or billing mutation. Existing production session scripts must not be invoked: their broad reset/config behavior is outside this envelope.

Ownership: a fresh cryptographic run nonce, at most20 Auth accounts with reserved run emails containing the run nonce, bound to an append-only ownership journal and returned UID; at most200 Firestore documents under a unique run prefix. Record attempted creations before sending. Record UID/email ownership and document names durably in private journals. Never enumerate/delete unrelated root collections. A replay adapter must map abstract resource names to owned runtime resources and remap references without erasing ownership or query order. Reset is implemented only by deleting journaled, readback-verified owned resources. No reuse of old tokens or transaction IDs.

Limits: at most2400 requests total, including400 Auth,1600 Firestore data,100 metadata/auth-acquisition and300 reserved recovery requests; hard combined request budget and per-service subtotals. At most2 in-flight requests combined, one per service; token refresh is single-flight. Combined sustained rate at most4 requests/second with no burst beyond2. Wall limit1200 seconds including300 reserved for recovery; configuration mutation prohibited. Stop starting observations at the earlier of900 seconds, recovery reserve threshold, unexpected error class, ownership/config drift, budget exhaustion, or an unclassified P1/P2. A request must reserve its full bounded deadline before starting. Streams, unbounded retries and contention experiments are excluded from the first batch.

Cost: proposed maximumUSD1 in incremental metered usage. Before approval, calculate an upper estimate from the explicit request/resource limits using owner-approved current tariffs; if that cannot be bounded, the unit remains blocked. Billing alerts are not an immediate hard stop and cannot replace request/resource limits. No SMS, functions deployment, new indexes or paid external services are allowed.

Approval validity: one batch within24 hours of recorded owner approval, bound to project/database/profile, frozen observer and case-manifest hashes, budgets and nonce. Any expansion, retry batch, budget increase, configuration change or expired approval requires a new envelope decision. Input combinations within the approved abstract operation/namespace/budget scope do not require case-by-case approvals.

Authentication and recovery: verify actual administrator token expiry before each privileged request, reserve acquisition/expiry-verification/subsequent-request time, latch failures and never fall back to unverified stale credentials. Preserve300 seconds and300 requests for resource verification/deletion. On incomplete cleanup, stop the batch, report unrecovered resource counts and retain private journals; only separately scoped ownership-verified recovery may continue. Do not claim completion while UID/email or document absence remains unconfirmed.

Concurrency/exclusions: revision3 and any other Auth configuration experiment must not share uncoordinated project settings. Rules/index/configuration mutations require a separate project or an explicit exclusive lease and separate approval; they cannot be added silently. Technical review, owner execution permission and result acceptance are distinct records. The next executable production adapter must enforce this envelope before it can be proposed for an actual batch.

## Implemented first-batch subset

The [candidate manifest](../../spec/compatibility/broad-batch-candidate.json) and [adapter](../../tools/compat-broad/batch_adapter.py) implement a narrower subset of this proposed envelope: 19 Auth checks and 27 Firestore diagnostics, at most three account attempts and eight document targets, no transactions or collection-group queries. Collection IDs remain `tf` and `broad` beneath unique run parent documents. The adapter's ownership marker is the random namespace/email plus the private journal and verified UID binding; it does not claim a server-side immutable account field.

Read-only preflight includes project identity, database edition/location, the exact approved Auth configuration digest and versioned Database settings projection digest and API-key project ownership. API-key lookup needs the existing `apikeys.keys.lookup` permission; the adapter never changes IAM to obtain it. Missing metadata access blocks execution. Baseline digests, owner identity/reference, approval time window and tariff confirmation are deliberately absent from the candidate; preparing this code does not grant permission to acquire credentials or contact the oracle.

The numerical estimate is approximately USD0.3052 using deliberately conservative planning rate ceilings, not verified current SKU prices. It budgets document operations, index reads, one month of worst-case document/index storage, network transfer and three Auth monthly active users, without deducting shared free quota. The two queries are direct collection queries over at most one owned document each. An owner must confirm that location/SKU tariffs fit the recorded ceilings and bind that confirmation and date into the approval; otherwise execution is refused. The estimate's assumptions and units are in the manifest. [Firestore billing](https://firebase.google.com/docs/firestore/pricing) describes the charged dimensions, and [Firestore limits](https://firebase.google.com/docs/firestore/quotas) supplies the conservative per-document index storage allowance.

A consumed nonce is recorded under the operator's home state directory before any production operation. The same nonce cannot start another batch through this adapter. Approval files are owner records, not AI-generated permissions or cryptographic attestations. All planned remote operations remain unexecuted in this milestone.


## Initial46 execution input package

The adapter's offline `--prepare-inputs` option assembles the frozen execution commit, observer and manifest hashes, comparison contract, Database projection contract, exact case/resource/request/cost limits and recovery policy in one JSON package. `ownerInputs` and `permission` remain unfilled. A prepared package is deliberately rejected by production admission; owner identity/reference, approved current projection/Auth baseline, location/tariff confirmation, validity window and unused nonce must come from an explicit owner decision. No new oracle metadata acquisition is performed by preparation.

The full parsed Database response digest remains acquisition evidence. Only `earliestVersionTime` is excluded from the approval projection; all other and unknown fields remain significant. The adapter checks this same contract before observations and after recovery, records both observations and their projection version/hashes, and refuses unconfirmed drift. Approved execution requires the exact clean frozen commit as well as the manifest/observer/comparison contract hashes. Follow the commands and exit-status contract in the [batch README](../../tools/compat-broad/README.md).
