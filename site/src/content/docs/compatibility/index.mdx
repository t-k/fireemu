## Products

Every product in the Local Emulator Suite of `firebase-tools` 15.28.2, the official emulator release Fireemu is compared with, and the surfaces Fireemu adds.

<ProductTable />

Fireemu is compatible with the Local Emulator Suite products that firebase-tools 15.28.2 ships and that Fireemu serves with parity (Cloud Firestore, Firebase Authentication, Cloud Storage for Firebase, Cloud Functions, Cloud Pub/Sub and Eventarc, with Security Rules on the Firestore and Storage surfaces), under the `emulator` compatibility profile and the evidence recorded in [`spec/compatibility/contract.json`](https://github.com/fireemu/fireemu/blob/main/spec/compatibility/contract.json). It makes no complete-suite and no unqualified superset claim, because:

- the Realtime Database and Firebase Hosting are served without a parity claim against the official emulator (an open gap; both are verified against production for recorded cases);
- App Hosting and Data Connect are deferred;
- Firebase Extensions is not planned.

## Fireemu, the official emulator and production

Differences that most often change a test result. Fireemu's column is the default `strict` profile.

| Behavior | Production | Official emulator | Fireemu |
|---|---|---|---|
| Query without its composite index | Refused | Runs | Refused; runs and reports the missing index with `firestore.missingIndexes: "report"` |
| Firestore client request to a project without Security Rules | Refused | Allowed | Refused |
| TOTP multi-factor authentication | Supported | Not available | Supported, through the project's MFA configuration |
| Request naming a tenant that does not exist | Refused | Creates the tenant | Refused |
| `beforeEmailSent` blocking function | Runs | Not run | Runs |
| App Check | Supported | Not available | Debug tokens; no attestation providers or replay protection |
| Scheduled functions | Run on Cloud Scheduler's schedule | Not run on a schedule | Run on a virtual clock you control |
| Unsigned mock ID tokens in Security Rules | Refused | Accepted | Accepted by default; refused with `productionExact` |
| Declared Storage upload checksums | Verified | Not verified | Verified |

## Production verification

Fireemu compares its answers with recordings taken from real Firebase projects. An area is **verified against production** when every condition in its frozen inventory matches the recordings, or differs only in a reviewed and documented way (a known difference). An area still being worked on is marked **In progress**, and its counts describe recorded conditions, not verification of the whole area.
