## Offline recordings

`recordings.mjs` extracts only the finite allowlisted SDK values, types, request method/path, header names and fixed request constants used here. It deduplicates repeated log polls by their original entry identity, rejects contradictory duplicates and refuses to count overlapping original event identities as independent recordings, including subsets with Tasks removed. The overlap guard conservatively rejects any shared original log-entry ID hash, including possible legitimate ID reuse across different recordings; it does not compare complete log resources or establish a universal independence proof. Equal masked SDK values alone do not trigger this guard. The selected original entry-ID sets of the two events passes and the Tasks pass were checked privately and are pairwise disjoint, and the three journals differ. Original identifiers and SHA-256 custody receipts remain private; public provenance uses only `pass-1`, `pass-2` and `tasks-pass-2`. Identity aliases preserve selected types/formats. Synthetic replay inputs remain explicitly distinguished from observed expectations. Unknown payload fields or request shapes fail extraction. Task-body masking accepts only the recorded two-field, unescaped-string lexical shape, rejects duplicate keys and escaped identifiers before publication, replaces each field by its own alias, and reparses the result against the exact synthetic payload. This is an offline tool and does not make production requests.

To extract the two explicitly selected journal/result pairs, run `node conformance/src/functions-python/recordings.mjs FIRST_JOURNAL FIRST_RESULT SECOND_JOURNAL SECOND_RESULT PRIVATE_CUSTODY`. The custody output must be under a private `docs.local` directory and must not exist; stdout contains the safe fixture pair.
