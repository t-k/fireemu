Fireemu is a local emulator for testing applications built with Firebase. It aims to match production Firebase behavior, so you can test locally and in CI without using a real Firebase project.

The Firebase Local Emulator Suite is Google's official tool. It covers more products than Fireemu, and it is the right choice when you need one of them. Fireemu has a narrower aim: tests whose results carry over to production, in CI and on a developer's machine.

## What Fireemu adds

The Local Emulator Suite is built for local development of a Firebase app. Fireemu adds checks that production applies and that matter for CI:

- **Configuration that production requires.** A Firestore query whose composite index is not declared in `firestore.indexes.json` is refused under `strict`.
- **Features the official emulator does not serve.** TOTP multi-factor authentication, App Check with debug tokens and, under `strict`, the `beforeEmailSent` blocking function.
- **Control over test execution conditions.** Set an arbitrary start time and move a virtual clock to run scheduled functions without waiting for the real schedule.

## Production first

Where the official emulator and production Firebase differ, Fireemu follows production under its default `strict` profile, and records the difference. The exceptions are the development defaults described below. The answers keep production's wording and status codes, so the errors your application handles in tests are the errors it will meet after you deploy.

Each behavior is checked against recordings from real Firebase projects. The [compatibility tables](../../compatibility/) list every area that has been verified this way and how many conditions it covers.

Some production behavior is costly in a test: production needs signed tokens, signing keys, or a feature enabled through an Admin API call. Fireemu keeps a development default that works without setup for each of these, because reproducing them exactly would slow tests down without finding more bugs. Each one is documented and has its own setting; `productionExact`, an advanced switch, restores production's behavior for all of them. See [Where Fireemu departs from production on purpose](../../guides/profiles/#where-fireemu-departs-from-production-on-purpose).

## Built for tests

- **One command for CI.** `fireemu exec -- npm test` starts the emulators, runs your tests with the emulator environment variables set, stops everything and returns the test command's exit status.
- **Reuses your `firebase.json`.** Rules, indexes, Functions codebases and ports are read from it on every start.
- **Explains denials.** Each Security Rules denial is printed with the conditions that were evaluated and their results.
- **Independent test worlds.** The `fireemu/testing` helper starts isolated emulator instances with their own clock, Rules, Functions and data, for parallel integration tests.
- **A single native binary.** See [Performance](../../compatibility/performance/) for the measured numbers and their conditions.

## What it is not

Fireemu does not reproduce real quota accounting, billing, IAM, organization policies, regional or network differences, or service rollouts, and local performance does not predict production latency. See [Limitations](../../compatibility/limitations/).

:::tip[Keep a production check]
Fireemu is still in development. For the features and critical workflows your application uses, run the same tests against Fireemu and a dedicated Firebase test project (not your live project), and compare the results before relying on Fireemu alone in CI.
:::
