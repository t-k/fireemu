# Immutable historical compatibility checks

Run `uv run --project tools/compat-inventory --locked --python 3.12 tools/compat-history/history.py --check` after changing runtime sources. The original frozen publishers bind their recorded artifact to source bytes and therefore must run in their historical source context, not against a newer runtime.

The runner pins reviewed commit `672db735ad36dc8f473b98bac2906f19f37bb70b` in code; receipt fields cannot select executable revisions. It compares the dedicated historical corpora, publisher entry points, evidence, approval and generated-page bytes and file membership in the current tree with that anchor before creating an independent temporary local Git clone. Added ignored evidence is rejected too; only ignored Python cache directories under tools are excluded. Shared `tools/compat-inventory` helpers may evolve in the current tree, but the complete old helper and test tree is verified and executed only inside the detached anchor checkout, so current helpers cannot enter the historical run. The runner uses a minimal child environment, disables uv configuration and pytest plugin auto-loading, and creates an owned temporary Python environment. It trusts the `git` and `uv` executables resolved from the invoking host's `PATH`, as the CI and documented local invocation already do. It then runs the original complete offline suite and all eleven publication/approval checks in that checkout. Missing Git history, changed frozen bytes and command failures fail closed. No remote fetch or Firebase request is made by the runner; uv may install locked dependencies from its package cache/index. The owned clone and Python environment are removed afterward, and current immutable files are checked again even when an archived check fails.

CI fetches the needed history and runs new revision tests/checks separately on current sources. Frozen tests are not silently discarded or counted as tests of the patched artifact. Existing approval pages remain bound to their original artifacts and subjects. Do not edit frozen files to satisfy a new runtime; use a new versioned evidence directory and subject. Changes to the anchor or frozen-path policy require explicit review and must not be derived from receipt data.

The new runner does not authenticate Git authors or grant human approval. It preserves the established trust boundary and detects drift against a fixed repository commit. Run `uv run --project tools/compat-inventory --locked --python 3.12 -m pytest tools/compat-history -q` for real-Git mutation and cleanup tests.
