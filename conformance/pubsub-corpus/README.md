# Pub/Sub streaming substrate

These modules are offline library components for a future guarded StreamingPull collector, not a production executor. They create no connection, session, credentials or files. The guarded collector must supply owned HTTP/2 transport, authoritative admission, durable receipt storage and bounded credentials. Production requests remain coordinator-only.

`streaming-frames.mjs` is a pure incremental, identity-encoding frame decoder. It preserves raw chunk bytes and candidate message order across split or coalesced envelopes, including empty messages, with independent message/total/frame/chunk caps. Malformed compression, oversized advertised lengths, incomplete termination or overflow stop further input; clipped raw bytes carry explicit truncation. A bounded rolling prefix refuses reflected credentials spanning chunks before emitting the credential-completing receipt. Input snapshots and returned string receipts cannot mutate parser state. The guarded recorder must durably persist raw receipts before treating candidates as evidence. Complete framing alone says nothing about peer status, delivery, cancellation, half-close, process containment or compatibility. This module creates no connection, session, credentials or files; the complete guarded StreamingPull transport remains separate work.

`streaming-write-gate.mjs` is injected outbound admission, with one opening and finite action/frame/envelope-byte reservations. It refuses concurrent callers before buffering, freezes frame bytes before asynchronous work, durably records intent, repeats awaited authority and requires a synchronous live check immediately before the reviewed synchronous issue callback. Half-close closes only the write direction; explicit recipe cancel has its own intent. Emergency containment immediately stops new admission independently of recipe authorization. Awaited callbacks share one monotonic deadline, and pending callbacks, containment failures or Promise returns from synchronous interfaces require parent-supervised termination. A settled Promise still violates the synchronous source contract. Attempted, known local issue and acknowledged issued receipts remain distinct; a lost receipt is uncertain and cannot be retried. `issuedActions` counts only issue calls that returned synchronously without throwing. An issue call that throws or returns a Promise was still invoked and may have sent bytes: it stays attempted and unknown (`unknownActions`) and opens no direction, so a zero `issuedActions` never means that nothing left the process. Both also set `terminationRequired`: a Promise return because work started by the callback may still be running, and a synchronous throw because a native write can fail after some bytes have left, which the gate cannot rule out. A failure before `issue` is invoked (authority, durable intent, live check) sent nothing and does not by itself require termination. Stop-origin labels are caller-supplied lifecycle facts, never evidence of peer status. `terminationRequired:false` is not proof of transport or process quiescence. All callbacks must be reviewed and run in the independently supervised collector; racing a deadline cannot stop arbitrary callback effects. Incoming HTTP2 evidence, header/event bounds, terminal chronology and verified teardown remain separate integration work.

`streaming-receipts.mjs` admits inbound raw data, ordered duplicate metadata pairs with flags, and lifecycle facts into a finite serialized queue. It charges empty events and enforces independent data, chunk, frame, metadata byte/event/pair and total event bounds before buffering. Raw receipts must be acknowledged by the injected durable store before candidate frame observers run. Observer attempts and acknowledgments remain separate; missing persistence acknowledgments leave unknown events. Literal, split data and decoded binary metadata credential reflection is refused before storage. Stop, drain and all callbacks share one monotonic deadline; pending callbacks or unacknowledged owned stop require independently supervised termination. The injected owned stop callback is requested once and cannot prove actual process or transport quiescence. Queue results do not classify peer terminals, establish delivery, or complete a production recording. The reviewed collector still needs owned HTTP/2 integration, terminal chronology and verified teardown.

Both streaming helpers accept an optional absolute monotonic `deadlineAt` in the `performance.now()` clock domain. The owned bridge must supply the same deadline unchanged to both helpers; it must be live and within the finite `wallMs` limit at construction. Timers, admission and draining use that deadline, including idle sessions. Standalone callers may retain the relative `wallMs` default. Gate containment begins synchronously after its pending callback is registered and receives the bounded stop `origin`; receipt owned stop receives its bounded `reason`. Callback completion is still asynchronous and cannot prove native shutdown. An ordered durable journal must run independently of frame observers: an observer awaiting a guarded write must never hold the journal needed to persist that write's intent. Actual event chronology must be stamped at native callback and issue boundaries, rather than inferred from these separate helper counters or persistence order.

`streaming-journal.mjs` serializes acknowledged byte records independently of frame observers, so an observer awaiting a later outbound intent does not hold the durable journal chain. It reserves entry and single/total byte limits before snapshotting, obtains byte-view metadata through intrinsic getters, and rejects raw property reentrancy. Records must already be credential-screened by the caller. Exact snapshots, hashes and sequence tickets describe append order and storage acknowledgments, not native event order or proven filesystem durability. Failed acknowledgments stop later writes without retry; admitted records may drain after a capacity refusal. Owned stop starts inline before draining. All three streaming lifecycle components check monotonic time when accepting stop acknowledgments and completing drain, so late Promise settlement cannot beat an overdue timer or restore an uncertain report to clean containment. Actual connection, peer terminal chronology and independently verified native/process teardown remain separate work.

`pubsub-streaming-properties.test.mjs` replays 300 fixed seeds per property: the frame decoder against a whole-stream reference decoder under random caps, partitions, corruptions and reflected credentials; well-formed round trips; the write gate envelope decoded back from arbitrary byte views; the write gate against a reference model of reservations, synchronous refusals, injected failure points, direction and stop origin; and the journal and receipt queue against sequential reference models over random operation sequences with explicit drain points, hung storage callbacks and drains after the deadline (mocked clock and timers). Each property also asserts that its generator reached every refusal reason, so it cannot pass vacuously.

Source-only verification:

```sh
node --test conformance/src/pubsub-streaming-frames.test.mjs conformance/src/pubsub-streaming-write-gate.test.mjs conformance/src/pubsub-streaming-receipts.test.mjs conformance/src/pubsub-streaming-journal.test.mjs conformance/src/pubsub-streaming-properties.test.mjs
```
