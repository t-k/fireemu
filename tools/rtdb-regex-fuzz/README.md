# Realtime Database regular-expression differential fuzz

Compares `matches()` in Realtime Database rules between fireemu and the official database emulator (firebase-database-emulator v4.11.2), both on loopback. Each generated subject, pattern and flags gives two rules, the match and its negation, so a difference shows in the polarity where it lets a read through.

- `gen.py` generates expressions from the grammar fireemu accepts: classes and ranges, escapes (`\w \d \s \S \W \D` and escaped punctuation), the `i` flag, astral and full-width characters, KELVIN SIGN, LONG S, dotless and dotted i, and the empty string; `edges` adds grammar edges (operators that start an alternative, empty groups, stray braces, `//`). Each run also writes `<corpus>.coverage.json`, the count of every production generated.
- `probe.mjs` judges each expression in every rule context (ruling 15): as `.read` of `/t/$k` read at `/t/o` by a GET without and with a query, by an event stream without and with the query and by a realtime listen, as `.write`, and as `.validate` beside `.write: true`, each signed in and anonymously, fourteen cells in all. It signs in as the user of an unsigned token without `aud`, which both servers read as that user under the emulator profile (fireemu since review r6 S16b). Each worker reuses one namespace and seeds it again before every rules load and write.
- `gen2.py` and `gen9.py` are a second and a third independent generator (the r8 and r9 reviews wrote them without reference to `gen.py`); `round.sh` adds as many of their expressions, each with its negation, to every round. `gen9t.py` writes the r9 review's exhaustive tables: every ternary of two operand kinds in every operand position, and every query member against every operand kind (`pair.py` adds the negations).
- `gen11.py` is a fifth independent generator (the r11 review wrote it) for the write kinds: `.write` and `.validate` at the node, a child, the parent and `$other`, each judged by `write_probe.mjs` over 18 write operations (PUT, PATCH at the node, parent and root, POST, DELETE, WebSocket set and merges, onDisconnect set and merges, a transaction, a conditional write, a `.priority` path write and server values), signed in and anonymously, with the owner's read-back after each. Its corpus starts with controls whose bodies are fixed per operation, rows that failed open before review r11's fixes. `write_compare.py` reports a cell as FAIL-OPEN (BLOCKING) when fireemu allows what the official emulator does not; `round.sh` runs `WRITE_COUNT` entries (default 500) after the read cells. For a sliced corpus, pass its original zero-based entry offset after the worker count: `node write_probe.mjs <host:port> <chunk.json> <out.json> <workers> <offset>`. This preserves operation-body selection and row indices; `node --test tools/rtdb-regex-fuzz/write_probe.test.mjs` checks whole-corpus/chunk equivalence and rejects invalid offsets.
- `matrix.py` writes the exhaustive operator x operand, method x receiver, case-folding range and identity (objects compared through a ternary) matrices, and `run_corpus.sh` runs a fixed corpus in chunks against a fresh official emulator and fireemu.
- `JavaChars.java` prints the character classes of the Java runtime the official emulator runs on, and `java_chars.py` writes `crates/fireemu-core-database/src/rules/java_chars.rs` from them.
- `check_coverage.py` (with `gen_productions.py`) fails a round where a grammar production was generated fewer than `MIN_COVERAGE` times (default 5): every escape and class form, plain, lazy-looking (`+?`, `{2}?`) and chained (`**`, `{2}{2}`) quantifiers, top-level alternatives unanchored, half anchored and anchored, white space (ASCII, Unicode, format characters, U+0085, line terminators) and comments between tokens, both flags and the empty subject. `round.sh` runs it before probing.
- `compare.py` reports every row where the answers differ, per cell. A row is BLOCKING when a cell is allowed (200) on fireemu and not on the official emulator (denied, refused at load, or an internal error there), unless the official emulator cannot determinize the pattern (M14, listed); any other difference is a denial on fireemu's side and is listed.
- `cells_fixture.py` writes `crates/fireemu-adapter-database/tests/fixtures/rules-cells-official-emulator-4.11.2.json` from recorded runs (whole tables, and the differing rows of other corpora with the reason each is listed); `rules_cells.rs` checks it without the official emulator.
- `round.sh` runs one round against a fresh official emulator (it holds every namespace in memory, so each round starts it again).
- `select.py` builds the fixed corpus from recorded rounds: hand-written rows, rows with grammar edges, and seeded samples of denied and agreeing rows. The result is `crates/fireemu-core-database/tests/fixtures/rules-expressions-3-official-emulator-4.11.2.json`, which `every_recorded_pattern_decides_as_the_official_emulator_or_denies` checks without the official emulator, so CI runs it.

The official emulator stalls and runs out of memory on wide ranges beyond ASCII under `i` (`/^[😀-￿]+$/i`); `gen.py` keeps such ranges narrow.
