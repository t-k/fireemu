# FS-CONFIG-LIFECYCLE oracle preparation

This directory classifies the Firestore Admin API v1 management surface and prepares one bounded, reversible observation of the twelve in-scope management cases. Nothing here contacts Google or reads a credential outside the O8 launcher's private handoff, and no production run has happened.

`surface_matrix.py` is the classification. Its denominator is the Discovery document pinned at `spec/compatibility/upstream/2026-09-09-retry/discovery.json`, so the enumeration is reproducible without a fetch. Each of the forty-two management methods is placed in exactly one of three classes with a rationale, the data-plane consequence that survives the classification, and the `file:line` where the behavior lives in this checkout. The module also classifies every field of the Database resource and carries five repair tickets, three of which cite the commit that fixed or narrowed them. `--write` publishes `spec/compatibility/fs-config-lifecycle-surfaces.json`; `doc_render.py --write` renders `docs/compatibility/fs-config-lifecycle-classification.md` from the same matrix.

`cases.py` compiles the twelve cases from one 32-character hexadecimal nonce: the database projection and enumeration controls, the time-to-live and single-field-exemption patches with their baselines, readbacks and reverts, the field listing and the operation poll. The thirteen cases that created or deleted a named database were dropped under the 2026-09-18 owner decision. Every request key is checked against the pinned Discovery document. `manifest.py` freezes the inputs, the enforced budget, the permission envelope, the owner preconditions, the abort rules, the owned-resource ledger and the shared Ledger lock scopes. `rehearsal.py` replays the recovery path offline under nine injected failures.

`lifecycle_gate.py` charges every request before it is sent and enforces the request, wall, cost and permission-expiry bounds, keeping a recovery reserve the observation phase cannot spend, and journals each configuration change as a locked step with its pre-value digest, post-value digest and restore state. `lifecycle_collector.py` drives the cases through an injected transport behind that gate, reverts on every stop path and reconciles the owned field listings and the enumeration; raw bodies stay in the private run directory and the result carries digests and type shapes only. `comparator.py` compares two collection records case by case and classifies MATCH only when the production side is bound to a `VerifiedAcquisition`, the object `lifecycle_production.verify_saved` builds from a saved O8 receipt directory and its shared Ledger row; a record that merely carries the `fixed-production-wire` label is REFUSED with a named reason, so a relabelled local collection can never read as a production comparison (owner review d7f7ce184, finding 2).

`lifecycle_descriptor.py`, `lifecycle_admission.py`, `lifecycle_production.py` and `lifecycle_o8.py` are the O8 boundary on the shared core: descriptor, frozen inputs and O7 checks, the shared Ledger reservation under EXCLUSIVE field-configuration locks, and the launcher. `lifecycle_production.verify_saved` is the read-only verified-input boundary for the comparator: it re-reads a receipt directory, checks the frozen inputs, gate snapshot and evidence digests the receipt names, the reviewed worker digest, the attested credential preflight, and the Ledger row and gate path the ticket claims, and returns the production record together with the acquisition object the comparator requires, registered by identity so `compare()` refuses an object it did not build. A proof Ledger is refused as the anchor unless `synthetic=True` is passed, and the object and the comparison then carry `synthetic: true`, which keeps `acquisitionValidated` false. The Ledger anchor binds the reservation (claim digest, gate plan digest, generation, nonce digest, gate path), not the bytes observed after it; the receipt, gate snapshot and collection digests are checked against each other inside the directory until a shared `attach_evidence` Ledger transition exists. `lifecycle_preflight.py` attests the bearer before OC-01 (frozen principal, scope, lifetime covering the wall plus the recovery reserve) through the request-byte lane's reviewed verifier. `lifecycle_https_worker.py` and `lifecycle_remote_transport.py` are the fixed-origin wire, reachable only on a consumed capability. `lifecycle_local.py` rehearses the campaign against an owned fireemu over loopback and publishes versioned records under `spec/compatibility/broad-runs/`; `fake_admin.py` is the in-memory Admin API the tests and the temporary-Ledger proof drive.

The shared Ledger cannot release a configuration-only reservation today, because `shared_gate.py` refuses a plan that owns no document and every terminal Ledger transition re-reads that Gate; `lifecycle_admission.release_supported()` says so, and a clean run ends held with a typed release-blocked record.
