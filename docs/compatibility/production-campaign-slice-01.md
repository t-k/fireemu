# Production-candidate campaign slice 01

This is an offline, unapproved proposal generated from the existing `shared_cases`, `batch_adapter`, `shared_gate` and comparison contracts. The checked-in [proposal](../../spec/compatibility/broad-runs/prod-campaign-slice-01.json) does not contact Google or Firebase, acquire ADC credentials, or assign owner, permission, window, nonce or current-environment inputs.

Six Firestore Standard Query Explain recipes are accepted by the existing local shared gate: `runQuery` and `runAggregationQuery`, each in plan-only, analyze and empty-analyze forms. Each recipe has a concrete POST path and body, two fresh-nonce document targets, absence preflight, conditional setup, typed response collection, final state readback and journaled conditional cleanup. The existing adapter and gate counters reserve 12 observation requests, 6 recovery requests and 2 coordinator calls.

Four Explain boundaries remain explicitly outside this admission: authorization refusal requires Rules setup, and transaction ownership requires a rollback route that the shared cleanup contract does not dispatch. Ten existing Auth tenant boundaries are also retained as outside cases because the current Adapter has no typed tenant route admission. These cases remain listed with source references and reasons; no guard is weakened and no synthetic route or runner is added.

Validation compares the complete proposal with its canonical typed JSON contract, including its full case and job sets. The proposal binds the fixed source commit, collector, local-only transport, fresh namespace template, principal, setup/readback/cleanup obligations, comparator, request/time/cost/recovery counters and unset owner inputs. Artifact and configuration digests remain unset until a separately reviewed local execution. Query Explain pricing assumptions remain bounded planning inputs: plan-only uses one read unit without query/index reads, while analyze follows normal document and index-read accounting. Current location tariffs and index bounds are unset. See the public [Firestore pricing](https://cloud.google.com/firestore/pricing) and [Query Explain](https://cloud.google.com/firestore/docs/query-explain) documentation.

The campaign tests run real existing `batch_adapter.Adapter` dispatch through `shared_gate.Gate` against a fixture wire callback. They keep transport `collectionComplete`, recipe `stateValidation`, `cleanupComplete` and `compatibility` separate. A fully received changed or error array, including an HTTP 400 Query error array, remains collection-complete and can be compared as `compatibility=mismatch`; non-JSON or interrupted transport, preflight drift and incomplete cleanup remain non-green or indeterminate as appropriate. Each recipe validator distinguishes plan-only, ordinary analyze document rows, empty analyze and aggregation envelopes. Comparator admission replays the concrete campaign manifest and checks every request, method, path, body and order on both sides. Owned IDs are journaled before writes and final absence is required.

The saved result includes principal evidence recomputed from the actual local Adapter and Gate dispatch: the shared plan digest, job, nonce, local origins and dispatch-event request digests. Comparison verifies that evidence against the manifest and recomputes each observation and recovery response digest from its retained body, with a separate status equality check, before comparing response bodies; no declarative principal claim is accepted as execution evidence. Cleanup may omit a dispatch event only for the exact conditional DELETE skip receipt when its source read has no usable version. Every other cleanup operation requires exactly one verified event, extra events are rejected, and the final read of each resource must prove absence with HTTP 404.
